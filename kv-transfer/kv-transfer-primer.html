Reusing a KV cache is a representation-transfer problem, not a re-prefill problem

When production serving swaps between two sizes of the same model family — cost-quality cascading, mid-conversation switching, routing — the receiving model normally has to re-run the entire prefill forward pass on the accumulated context. This paper shows that's often unnecessary: cross-model KV caches share substantial linear structure, so a small, closed-form, per-head ridge regression — fit once on 500 calibration sequences, no gradient descent — can map a source model's KV cache directly into a target model's expected format.

00 · The reframing

Prefill's output is the KV cache — so reusing it is a representation problem

Production LLM serving increasingly relies on multi-model orchestration: cost-quality cascading, mid-conversation model switching, and routing across different sizes of the same family. Each swap forces the receiving model to re-prefill the entire accumulated context from scratch — a forward pass whose cost scales with model size and prompt length. Prefix caching only helps within one model; it does nothing across a model swap.

The paper's core move: since prefill's only output is the KV cache, reusing it across models reduces to a representation problem — transforming one model's KV cache into the format another model expects. The paper calls this cross-model KV cache transfer, and restricts the study to within-family transfer, where source and target share a tokenizer, core architectural choices, and substantial pretraining data.

The mapping is bidirectional: small→large transfer upgrades quality mid-session, large→small reduces cost. Across six matched-KV pairs from three families (Qwen3, Llama 3.1, Ministral 3), a closed-form linear mapper retains 73–98% of the receiver's standalone-prefill accuracy on four of those pairs, while two degrade sharply — and runs 2.7–25× faster than re-prefill. The rest of this page follows the paper's own derivation order: what structure the cross-model KV relationship actually has (§02), the three-part mapper built to exploit it (§03–05), a nonlinear extension for the pairs where linearity isn't enough (§06), and what actually predicts whether a given pair will transfer well (§07).

01 · §2.1, Problem formulation

Matched-KV pairs and the transfer objective

A source model 𝒮 has Ls layers; a target model 𝒯 has Lt layers. Both use grouped-query attention with nkvs and nkvt KV heads of dimension dhs and dht. For input sequence x=(x1,…,xT), layer l, head h of the source produces keys/values Ksl,h, Vsl,h ∈ ℝT×dhs. Source and target share a tokenizer within a family, so the input has the same length T for both.

Matched-KV definitionverbatim from the paper
A transfer pair has matched KV when nkvs = nkvt and dhs = dht,  even if Ls, Lt, or parameter counts differ across scales.

The goal is a mapping f: 𝒞𝒮 → 𝒞̂𝒯 from the full source cache to a predicted target cache, such that the target decoding from 𝒞̂𝒯 in place of its own 𝒞𝒯 produces equivalent outputs:

m( 𝒯(x; 𝒞̂𝒯) )  ≈  m( 𝒯(x; 𝒞𝒯) )     — Eq. (1)

for downstream task metric m. f decomposes into independent per-head mappings fKl,h and fVl,h that produce the target's keys and values for each layer and head. Transfer quality is measured by the target model's downstream accuracy, not by cache-reconstruction error alone — a distinction that turns out to matter a great deal (§07).

02 · §2.3, Linear structure in cross-model KV

Before choosing a mapper architecture: how much structure is actually here?

For each cache type C ∈ {Krope, Kstripped, V} and each triple of source layer l′, target layer l, head h, the paper fits a single-source OLS probe at the token level — a diagnostic, not the production mapper of §03–05:

Ĉtl,h = Csl′,h W + b,      W ∈ ℝdhs×dht,   b ∈ ℝdht     — Eq. (2)

Fit quality is measured by R², head-averaged, visualized as a heatmap: rows are source layers, columns are target layers. On Qwen3 14B→32B, a single source layer explains 56% of variance in the target's keys and 32% in values — rising to 79% and 65% with multiple source layers selected by greedy forward selection. The best single source–target cell reaches R²=0.81 (14B→32B) and 0.65 (8B→32B, a weaker pair) at the heatmap peaks.

target layer 1 → 8row = source layer 1 → 8

Four qualitative patterns fall out of this picture, all reproduced in the toggle above: (1) fit is well above zero along the diagonal — a large fraction of cross-model KV variance is already linear; (2) closer model pairs give sharper diagonals, larger gaps diffuse the pattern; (3) RoPE contaminates the fit — stripping it sharpens the diagonal, motivating §05; (4) K is consistently more predictable than V, typically by a ∼0.2 gap in head-averaged R².

How many source layers does the mapper need? Extending the probe with greedy forward selection (iteratively adding the source layer that maximally increases R²) shows complementary information spread across multiple layers: on Qwen3 14B→32B, k=1 captures only 66% of the k=all R² for Kstripped and 42% for V, with the largest gain from k=1 to k=4 and near-k=all performance by k=6. This motivates top-k source selection (§04).

03 · §3.1, Per-head ridge regression

One closed-form linear solve per (target layer, head)

Source and target differ in layer count, head dimension, and potentially KV head count. The mapper handles this by fitting an independent linear mapping per target (layer, head):

K̂tl,h = XKl WKl,h + bKl,h,     V̂tl,h = XVl WVl,h + bVl,h     — Eq. (3)

where XKl concatenates source key features from the k selected source layers (§04) and WKl,h ∈ ℝ(k·nkvs·dhs)×dht. Stacking N calibration tokens gives design matrix X ∈ ℝN×(k nkvs dhs) and response Y ∈ ℝN×dht. Ridge, not pure OLS, is used for conditioning — the feature dimension can reach tens of thousands at large k, and top-k selected source layers are by construction correlated, so X⊤X is near-singular:

Closed-form ridge solutionverbatim from the paper
W* = (X⊤X + λI)−1 X⊤Y,     λ=0.01     — Eq. (4)

X and Y are centered before solving, so W* above estimates the slope and the bias is recovered separately: b = Ȳ − X̄W*.

Calibration uses 500 FineWeb-Edu sequences of length 1024, stride-4 subsampled to N≈128K tokens per target head. Fitting takes ∼47–87 minutes per pair on a single 8×H100 node — no gradient-based training anywhere in the pipeline. A four-order-of-magnitude sweep of λ shows a wide flat region (collapse only at λ=1), and N=50 already lands within ∼1.6pp of the full N≈128K production fit.

Bars: predicted vs. actual target value per token. At λ→0, W swings to fit noise in the collinear direction; increasing λ shrinks and stabilizes it, exactly as Eq. (4) prescribes.

04 · §3.2, Cross-layer source selection

Every target layer gets its own top-k committee of source layers

Source and target have different numbers of layers, so which source layers should inform each target layer's mapping is not obvious. For each target layer l, the top-k source layers are selected by head-averaged R² (averaged over RoPE-stripped keys and values), and their KV features are concatenated to build the design matrix used in §03:

XKl = [ K̄sl1 ‖ K̄sl2 ‖ ⋯ ‖ K̄slk ]     — Eq. (5)

where K̄sli ∈ ℝT×(nkvs·dhs) concatenates all key heads from source layer li, and {l1,…,lk} are the top-k source layers for target layer l. XVl is built analogously from value heads. All heads within a target layer share the same selected source layers — cross-layer selection is a per-layer decision, not per-head. k itself is a hyperparameter, swept per pair over {1,2,4,6,8,10,12,16,20,24,all} and picked to maximize mean log-likelihood accuracy on held-in benchmarks.

Ablation confirms this is the largest single contributor. Reducing k from 8 to 1 on Qwen3 14B→32B drops K R² from 0.79 to 0.56 — a bigger swing than disabling ridge regularization or RoPE handling (full ablation table in §07).

05 · §3.3, Content-space (RoPE) mapping

Strip the rotation, fit in content space, re-rotate at the target's position

RoPE applies a position-dependent rotation to queries and keys; the cache stores only the rotated key kRoPE(t) = RΘ(t) kcontent. Fitting the ridge weights directly on RoPE-coupled keys works within noise on short-context benchmarks, but ties the fitted weights to the 1024-token position distribution seen at calibration. Decoupling position from content makes the mapper position-free and reusable at any length the target's RoPE supports — which matters when serving prompts up to 32K tokens.

Content-space mappingverbatim from the paper
K̂t = ( Ks RΘs−1(t) WK + bK ) RΘt(t)

Regression targets during calibration are built by stripping the target's RoPE from its ground-truth keys, so WK is fit entirely in position-free space. Since RΘ is orthogonal, the inversion RΘ−1 = RΘ⊤ is exact at negligible cost. Values carry no positional encoding and are mapped directly — only keys need this step.

The whole point of stripping at ts and re-encoding at a different tt: the fitted weights never see position at all.

06 · §4.4, Substituting MLP for ridge

Where ridge fails, a small MLP recovers most of the gap

A per-(target layer, head, K|V) MLP — two 1,024-unit ReLU hidden layers, trained with Adam on the same MSE loss as ridge — is dropped in at inference in place of the linear map. The only thing that changes versus §03 is the mapper's functional form; calibration data and downstream evaluation are identical.

The paper's reading: linear ridge is sufficient wherever the cross-model KV relationship is already linear; the MLP helps only where ridge falls short, not uniformly. §07 explains mechanistically what the MLP changes.

07 · §4.5, What determines transfer quality

Calibration R² does not predict retention — attention-output cosine does

Across the six matched-KV pairs evaluated in both directions, calibration R² alone fails to predict per-pair outcomes: Llama 3.1 8B→70B fits ridge at R²K=0.84 and retains 94% HellaSwag small-to-large but only 37% large-to-small; Ministral 3B→8B fits at the same R²K=0.84 and retains 93% in both directions. The same fit quality, very different downstream outcomes — because R² weights every channel equally, but attention doesn't: it scores K against the target's queries and weights V by the resulting attention pattern.

Attention-output cosineverbatim definition

Cosine similarity between the attention output computed from mapped KV and from ground-truth KV, averaged over layers and heads. Across 12 matched-KV pair evaluations from three families (six S→L and six L→S), mean cosine correlates with HellaSwag retention at Pearson r=+0.57, while calibration-domain R²K shows essentially no correlation (r=−0.20).

K-concentration

Project the mapper's per-token K error onto the right singular vectors of the target's per-head query matrix Qh, weight each component by its matching squared singular value, divide by the mean error across all components. Concentration >1 means error lands where attention reads.

V-concentration

Weight per-position V error by the squared ground-truth attention weight at that position, divide by the mean per-position error. Concentration <1 means error lands where attention ignores it.

Comparing ridge to MLP on the same four pairs makes the mechanism concrete: on the pairs where ridge falls short, the MLP substantially lowers K-concentration (Δ≈−2.5 avg) and raises attention-output cosine (Δ≈+0.45) — it isn't fitting the cache better everywhere, it's redistributing residual error away from the subspaces attention actually reads.

08 · §4.6–4.7, Multi-turn drift & latency

Does accuracy drift across turns, and how much latency does the mapper actually save?

Mid-conversation switching alternates between source and target across turns, so drift is measured on Qwen3 14B↔32B with CoQA: 100 conversations, ∼15 turns each, across five domains, scored by F1 against ground truth. Drift at turn t is the F1 gap between the target's standalone accuracy and the mapper's accuracy at the same turn.

small→large drift, turn 1→10widens by 1.7 pp
large→small driftgrows linearly, 0.33 pp/turn

Both slopes are too small to cause cascading failure within ten turns on this evaluation, though the linear large→small drift would still accumulate over very long sessions. Tuning k specifically for the multi-turn task changes drift by at most 2.0pp.

09 · Worked example

Hand-verified: Eq. (4) on four scalar calibration tokens

A minimal, fully checkable instance of Eq. (4): 1 source feature, 1 target feature, 4 calibration tokens. x = [1, 2, 3, 4], y = [2.1, 3.9, 6.2, 7.8] (roughly y≈2x, with noise), λ=0.01.

x̄ = 2.5,  ȳ = 5.0 xc = [−1.5, −0.5, 0.5, 1.5],  yc = [−2.9, −1.1, 1.2, 2.8] X⊤X = ∑ xc,i² = 2.25+0.25+0.25+2.25 = 5.0 X⊤Y = ∑ xc,iyc,i = 4.35+0.55+0.6+4.2 = 9.7 W* = X⊤Y / (X⊤X + λ) = 9.7 / 5.01 = 1.93613… b = ȳ − x̄·W* = 5.0 − 2.5×1.93613 = 0.15968…

Compare to plain OLS (λ=0): W*=9.7/5.0=1.94 exactly — ridge moves the slope by less than 0.2% here, because X⊤X=5.0 is nowhere near singular. This is the "negligible fit bias" the paper describes for well-conditioned fits, matching §03's finding that a four-order-of-magnitude λ sweep shows wide flat regions. The live §03 demo runs the identical closed-form solver — only the input data differs (two correlated features there, engineered to actually stress-test conditioning).

Constructed for this primer: the §03 toy ridge calibration set (6 tokens, 2 correlated features) and the §05 RoPE demo's content vector — illustrative inputs chosen to exercise the exact paper formulas, not values from the paper itself.
