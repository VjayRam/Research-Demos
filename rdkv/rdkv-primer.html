RDKV: eviction and quantization are the same knob, turned to different depths

Every KV-cache compression method before this one picks a token/channel importance score, then separately decides whether to drop it (eviction) or shrink it (quantization). RDKV notices that both are the same operation — assigning a bit-width — just evaluated at different points on one curve. Zero bits is eviction. A reverse water-filling argument then tells you, in closed form, exactly which bit-width every token and channel should get under a fixed budget.

00 · The reframing

Prior work treats eviction and quantization as two separate techniques

Decode in a KV-cache-served LLM is memory-bandwidth-bound: the whole cache is re-read from HBM every step, so throughput is a near-linear function of how much cache fits in memory. Two families of methods shrink it. Eviction (H2O, SnapKV, StreamingLLM) picks an importance score and keeps only the top-k tokens — a binary keep/drop decision. Quantization (KIVI, ZipCache) keeps every token but represents it with fewer bits. Hybrid methods (SnapKV+ZipCache) run eviction first, then quantize whatever survives — two independent stages with a hand-tuned split between them.

RDKV's core move: stop treating "keep at full precision," "keep at low precision," and "drop entirely" as three different mechanisms. They're one mechanism — assign a bit-width bu ∈ {0, 2, 4, 8, 16} to each cache unit — evaluated at different points. bu=0 is eviction. bu=16 is full-precision retention. Everything between is quantization. One optimization problem, one budget, one allocation curve.

The rest of this page follows the paper's own derivation order: quantify what removing a token or channel costs (§01–03), quantify what quantizing it costs (§04), combine both into one rate-distortion objective and solve it in closed form (§05), discretize it for real hardware bit-widths (§06), then run the whole thing as a three-stage pipeline once after prefill (§07–09).

01 · Notation

A decoder-only transformer, one layer-head pair at a time

A decoder-only transformer has L layers, Hq query heads, Hkv KV heads (group size g=Hq/Hkv), and per-head dimension d. For a prefilled context of T tokens, the KV cache per layer is K,V ∈ ℝHkv×T×d, with

aτ,t = softmaxt( qτ⊤ kt / √d )     oτ = ∑t aτ,t vt

Every cache unit u — a token in the V cache, or a channel in the K cache — gets assigned a bit-width bu ∈ 𝔹 = {0, 2, 4, 8, 16}, from outright removal to full FP16 retention, subject to a total bit budget B. The goal: find {bu*} minimizing the distortion this induces in the attention computation. Everything from here derives one weight per unit, then one shared allocation rule.

02 · §3.1, Prop. 3.1

Evicting a V-cache token perturbs the attention distribution — by exactly its own weight

Each token enters the output as one weighted term aτ,t vt. Evicting token t zeroes its logit; softmax automatically renormalizes the rest:

âτ,t = 0,     âτ,t′ = aτ,t′ / (1 − aτ,t)    for t′ ≠ t     — Eq. (1)

Measuring the change with total-variation distance between aτ and âτ collapses to something clean:

Proposition 3.1 — token weight in V cacheverbatim from the paper
‖aτ − âτ‖TV = aτ,t    for each query τ.
wt := ∑τ aτ,t.     — Eq. (2)

wt is just cumulative attention — the same score H2O and SnapKV already use to rank tokens for binary keep/evict. RDKV's twist: here it's not a ranking score, it's a multiplicative coefficient in an objective function. Its magnitude, not just its rank, determines the bit-width. And because the attention computation is linear, the same coefficient also governs the cost of quantizing (not just evicting) that token: quantization noise δvt propagates to the output as δoτ = aτ,t·δvt, scaling with the exact same wt. That's what unifies eviction and quantization under one weight.

03 · §3.1, Prop. 3.2

Zeroing a K-cache channel is a rank-one perturbation to every logit at once

The K cache uses a different compression unit: persistent per-channel outliers make the channel (not the token) the natural thing to prune. Channel c holds the T scalars {kt,c}t=1T. Since every logit is an inner product qτ⊤kt/√d, zeroing channel c removes that one coordinate's contribution from every logit simultaneously:

δZ = −(1/√d) · Q[:,c] · K[:,c]⊤    — Eq. (3)

This is a rank-one outer product; its spectral norm gives the per-channel weight:

Proposition 3.2 — channel weight in K cacheverbatim from the paper
wc := (1/√d) · ‖Q[:,c]‖2 · ‖K[:,c]‖2.     — Eq. (4)

Channels whose Q- and K-columns are both large drive the logits strongly and are expensive to remove. (This weight coincides with what ThinK derives independently via Frobenius minimization — the paper notes this explicitly.) As with wt, quantizing rather than zeroing a channel produces a logit perturbation that scales with the same wc, so it too serves as the cost coefficient for both regimes.

04 · §3.1, Bennett's approximation

How many bits does a given distortion weight actually buy?

wt and wc answer "how much does this unit matter." The other half of the objective is "how hard is this unit to compress" — its quantization hardness. Under Bennett's high-rate approximation, a uniform scalar quantizer with per-unit dynamic range Ru achieves per-coordinate RMS error σu · 2−b with:

σu := Ru / (2√3)

Multiplying the two together — how much a unit matters, times how much noise a given bit-width leaves behind — gives the full rate-distortion objective:

Eq. (5) — the rate-distortion objectiveverbatim from the paper
Δ𝔻({bu}) = ∑u wu σu 2−bu,    s.t. ∑u bu ≤ B.

The coefficient wuσu is what actually gets ranked in the next section — not wu alone. A high-attention token that happens to be easy to quantize (small dynamic range) can rationally get fewer bits than a lower-attention token that's hard to quantize (large dynamic range).

05 · §3.1, Theorem 3.3

The Lagrangian solution is reverse water-filling — in closed form

Minimizing Eq. (5) subject to bu ≥ 0 has an exact closed-form minimizer:

Theorem 3.3 — optimal bit allocationverbatim from the paper
bu* = [ log2( ln2 · wu σu / λ ) ]+

with λ>0 chosen so the budget binds. The water level λ/ln2 induces a hard phase transition: units with wuσu < λ/ln2 get bu*=0 — eviction falls straight out of the same formula that assigns quantization bit-widths to everything else. Tightening B raises λ and pushes more units past the boundary into eviction; loosening it promotes evicted units back to low-bit retention.

Bar height = continuous bt* (not yet snapped to hardware bit-widths — that's §06). The dashed line marks λ/ln2: any wtσt under it is evicted (hatched). This is the exact formula above, solved by bisecting on λ until the budget binds — not a discretized or simplified version.

This is the paper's central claim made concrete: there is no separate "eviction module" and "quantization module." One threshold, sliding with the budget, produces both.

06 · §3.1, Eq. 6 & Appendix C, Algorithm 2

Real hardware only speaks {0, 2, 4, 8, 16} — solve the discrete version

Theorem 3.3 gives a real-valued bu*, but GPU kernels need one of a fixed set of bit-widths. The paper replaces Bennett's smooth curve with an empirically calibrated per-coordinate distortion table εu(b) (measured offline on LongBench prefill sequences, including b=0 for outright removal — Appendix B), and solves the resulting multiple-choice knapsack problem:

Eq. (6) — discrete MCKPverbatim from the paper
{bu*} = argminbu∈𝔹 ∑u wu εu(bu)    s.t. ∑u bu ≤ B.

Lagrangian relaxation decouples this into independent per-unit table lookups. One-dimensional bisection on λ recovers a feasible allocation in O(U|𝔹|) time — negligible next to prefill. This is Algorithm 2 (full pseudocode in §09), reproduced here exactly:

07 · §3.2, Fig. 2

Three stages, run once per layer-head pair, right after prefill

Under an FP16 reference, a per-head budget of Btok tokens corresponds to Bhead = 2·Btok·d·16 total bits, split equally between V and K: BV=BK=½Bhead. The pipeline (illustrated in the paper for 8 tokens and 8 channels, reproduced at that same size below):

Stage 1 — weighting

From the prefill forward pass, compute wt (Prop. 3.1) from the attention matrix and wc (Prop. 3.2) from Q/K column norms. Both come from the uncompressed cache, computed once — no value vectors or output residuals needed.

Stage 2 — V token allocation

Each token holds d scalars, so BV becomes B̄V := BV/d in summed-bit-width units. MCKP (Eq. 6) on wt determines 𝒯kept := {t : btV>0}. Evicted tokens are gone entirely.

Stage 3 — K channel allocation, on kept tokens only

The K budget BK is spent only across 𝒯kept — each channel now holds |𝒯kept| scalars, so B̄K := BK/|𝒯kept|. MCKP runs again, this time on wc (reused unchanged from Stage 1 — no second forward pass). V is allocated before K precisely so K's shrunken denominator reflects who actually survived eviction; reversing the order would waste K budget on soon-to-be-evicted tokens.

08 · §3.3, Fig. 3, Eq. 7

A mixed-bit allocation only helps if the cache stays packed in HBM

If quantized entries were unpacked to FP16 before the attention kernel reads them, peak memory wouldn't move and dequantization would add pure latency. The pipeline output has to stay packed while dequantization fuses into the attention kernel. The obstacle: tokens within one head now carry different bit-widths, but GPU kernels want uniform-precision segments. RDKV's answer is three storage zones per (ℓ,h) pair, each with one uniform dequantization path:

TriZone layout, driven by the §07 pipeline's own output above
Zone A — packed, quantized (old cache)Zone B — FP16, retainedZone C — FP16, new decode tokens

Zone A: retained K rows from 𝒯kept plus V rows with btV∈{2,4,8}, grouped into uniform-bit sub-segments. Zone B: V rows with btV=16 — their K rows still live in Zone A, since K bit-widths follow the independent per-channel allocation, not bV. Zone C: newly generated tokens, growing by one entry per decode step.

At each decode step the query attends over both zones at once — quantized old K concatenated with FP16 new K — and the output splits into three value sources matching the three zones:

Eq. (7) — packed-decode output decompositionverbatim from the paper
oτ = ∑t∈𝒯kept\𝒯V16 aτ,t·v̂t  (Zone A, quantized V)
    + ∑t∈𝒯V16 aτ,t·vt  (Zone B, FP16 retained)
    + ∑t∈𝒯new aτ,t·vt  (Zone C, FP16 new)

K-cache dequantization is fused algebraically rather than materialized: per-channel quantization stores k̂t,c = sc(k̃t,c − zc), so the kernel rewrites qτ⊤k̂t as a sum over (scqτ,c)·k̃t,c minus one per-query-head bias subtracted once — never writing a dequantized FP16 tile back to memory at all.

09 · Appendix C

Algorithm 1 & 2, in full

Algorithm 1 — RDKV: Rate-Distortion KV Cache Compressionverbatim pseudocode structure
Input: prefill cache K(ℓ),V(ℓ) per layer ℓ; per-head budget Bhead;
    observation window Sw; pooling kernel w; bit-width set 𝔹={0,2,4,8,16};
    empirical distortion tables εK(b), εV(b)
Output: TriZone packed cache for each (ℓ,h)

for each layer ℓ = 1,…,L do
  # Stage 1: weight computation
  A ← Softmax( Q[τ−Sw:τ](ℓ) K(ℓ)⊤ / √d )
  for each KV head h = 1,…,Hkv do
    wt(h) ← ∑τ,g aτ,g,t(h) for all t   ‣ V-cache token weight
    wt(h) ← AvgPool1d(wt(h), w)
    wc(h) ← (1/√d)·‖Q:,c(h)‖2·‖K:,c(h)‖2 for all c   ‣ K-cache channel weight
  end for
  # Stage 2: V-side token allocation (per head)
  BV ← ½Bhead;   B̄V ← BV/d
  for each KV head h do
    {btV}h ← MCKP( wt(h), εV, B̄V/T )
    𝒯kept(h) ← {t : btV>0}
  end for
  # Stage 3: K-side channel allocation (per head)
  BK ← ½Bhead
  for each KV head h do
    kavg(h) ← BK / ( |𝒯kept(h)| · d )
    {bcK}h ← MCKP( wc(h), εK, kavg(h) )
  end for
  # Stage 4: TriZone packing
  for each KV head h do
    sort 𝒯kept(h) by btV into sub-segments 𝒮2,𝒮4,𝒮8
    sort channels by bcK into segments; permute q to match
    quantize + byte-pack V sub-segments → Zone A(V); K rows of 𝒯kept(h) → Zone A(K)
    store {t : btV=16} V rows in FP16 → Zone B
  end for
end for
Algorithm 2 — MCKP: Lagrangian Bisection Knapsack Solververbatim, and implemented exactly in §06 above
Input: weights {wu}; distortion table ε(b); target avg. bits b̄;
    bit-width set 𝔹; tolerance δ; max iterations I
Output: bit-width assignment {bu*}

λlo ← 0;   λhi ← maxu wu
for i = 1,…,I do
  λ ← (λlo + λhi) / 2
  for each unit u do
    bu* ← argminb∈𝔹   wu·ε(b) + λ·b
  end for
  b̄cur ← mean({bu*})
  if |b̄cur − b̄| / b̄ < δ then return {bu*}
  else if b̄cur > b̄ then λlo ← λ
  else λhi ← λ
end for
return {bu*}

Default calibration (Appendix B): observation window Sw=32, pooling kernel w=5, K/V split rK=½ (ablated and found best across budgets), bisection tolerance 10−2, at most 64 iterations — every one of these is reproduced exactly as a default in the §06 demo above.
